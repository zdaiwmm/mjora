# App 版本与无线更新

“设置 → 关于与更新”显示已安装 App 的版本和构建号，与服务器版本分开。“已准备的版本”来自已配置的更新 Mac，并不代表已经安装。

配置了受信任更新 Mac 的私人构建，会在回到前台时检查已准备的新版本。自动检查至少间隔 15 分钟，同一版本提醒间隔 24 小时；也可以在版本页面手动检查。只有点“通过 Mac 安装”并确认后，才会请求安装。检查、点“稍后”、启动 App 或启动 Mac 服务都不会自行安装新版本。

Mac 需要开机、保持唤醒并已登录，手机需要已经配对且可通过网络连接。Mac 插网线、手机连接同一家庭局域网的 Wi-Fi 也可以；不要求两者使用同一个 Wi-Fi 名称。当前流程没有配置外网安装通道。手机或 Apple 工具需要解锁、登录时，页面会提示处理。安装会覆盖当前 App，可能打断尚未结束的传输，重新打开后由现有恢复流程继续。

更新主机只接受固定已签名安装包的发布编号，不接受任意下载地址、路径或命令。它验证版本、签名、目标设备、源码指纹与原有照片服务器配置，安装成功并核对手机版本后才更新自动续签使用的源码。确认请求十分钟内有效；过期后需重新确认。续签与版本更新使用同一把运行锁，续签持锁后会重新读取当前源码配置。

自动续签是另外一项 Mac 服务：它为已经安装的版本延长签名有效期，不会自动选择 GitHub 新代码。免费 Apple 账号的期限、登录状态和设备连接限制仍然适用。

签名后的 `.app`、配置、证书、连接凭据和安装回执保存在更新 Mac 的私人目录，不上传公共 GitHub。仓库保留源码、依赖锁和通用更新主机代码。准备下一版本需要先构建、检查、签名，再发布本地版本清单；这不是代码热更新或自动下载执行 GitHub 源码。

通用 Mac 服务位于 [mjora-server/host-tools/update-host](https://github.com/zdaiwmm/mjora-server/tree/mjora/host-tools/update-host)。私人构建的 `Imora/Resources/AppUpdateHost.json` 包含版本 1 配置、固定 HTTPS `/v1` 地址、专用根证书、独立更新凭据和主机编号；该文件已被 Git 忽略。服务端私钥不会进入 App，也不会改变系统的证书信任。未配置该资源的源码构建会显示“未配置无线更新”，其他 App 功能仍可使用。
