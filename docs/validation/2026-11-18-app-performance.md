## 已处理的根因

| 场景 | 原因 | 修改 |
| --- | --- | --- |
| 滚动 | 保存视口时扫描整库行、重新合并日期分区并在主线程编码 | 按现有索引访问可见行，复用日期拓扑，编码移至并发执行并校验版本、取消和账户 |
| 双指缩放 | 每个密度端点在主线程构建整库投影，再遍历所有照片寻找可见项 | 查询轻量日期/分区拓扑，只输出已捕获照片；缩放尺寸直接跟随手指倍率 |
| 年/月/全部 | 单张锚点配合淡入，滚动后锚点可能离屏，且可能等待大预览 | 多张可见照片共享空间转场，按当前可见封面重选锚点，使用仍然有效的现有图片开始转场 |
| 精选集 | 首次一次性构建屏幕外区块、地图及预览，重复查询相同封面 | 纵向按需创建区块，共享当前会话的封面请求与结果；仅访问精选集后开始首屏预取 |
| 详情 | 图片条对整个图库进行 SwiftUI 初始定位，工具栏快照先于真实附件显示；媒体安全区还会在同次布局中 34→82→34 往返 | 原生 collection view 以常量时间定位并复用可见图片；真实控件先挂载，媒体任务稍后启动；媒体安全区统一使用窗口物理安全区。详情冷打开与工具栏桥接成本仍未解决 |
| 视频详情 | 播放器尚未认领时已知时长未进入进度状态 | 由选中视频元数据初始化时长，准备期间保留真实进度控件 |
| 备份发热 | 索引准备允许保存至 32 路；`.fair` 仍允许完整并发，到 `.critical` 才暂停 | 索引阶段原件准备默认 2、上限 3，旧高并发值迁移至 3；后台、低电量及 `.fair` 降为单任务，`.serious/.critical` 暂停新增工作；显式备份也遵守实时热状态 |
| 失败刷新 | 刷新只读取统计，成功追赶后发生的本地授权错误还可能留下旧暂停 | 失败列表下拉刷新执行重试；共同入口重新验证旧暂停；成功后按剩余失败清除过期提示 |
| 失败诊断 | 多种错误均只保留 `other`，重复失败后无法回溯具体原因 | 在原有 250 项上限账本中保留最新一次的安全分类、阶段、数值码或校验状态；兼容旧记录，不保存路径、URL、响应正文和原始错误描述 |

额外审计并处理了以下问题。

- 本地缩略图每个调用都读取整份账户绑定、解码、编码并哈希。现在缓存账户命名空间，确认账户/绑定版本变化会失效；版本、像素、PhotoKit 修改校验及媒体授权仍分别保留。
- 备份索引刷新在主线程额外遍历所有记录提取远端删除保护。现在由索引 actor 随其他配对快照一起产生。
- 图片条拖动期间删除照片可能让布局数量与数据源不同。现在先更新几何并恢复有效选中位置。
- 图片条离屏及销毁时取消原生缩略图任务；失败状态通过单元格转发点击与辅助功能重试。
- 日历封面元数据更新后仍可能使用旧快照。收藏/编辑状态更新现在同步刷新日历来源。

## 度量边界

使用独立 iPhone 17 模拟器、iOS 27.2、优化编译 `-O`，本机 loopback 的 12,000 张合成照片及合成视频。未读取或修改真机用户照片。原 Docker 夹具当前不可用，本轮新 UI 夹具只用于交互与图片呈现，不替代真实 Immich 协议集成。

真机只读诊断另外确认了 iPhone 15 Pro 上的 32 路索引设置和 6 项保留失败，最高连续失败 126 次；旧账本全为 `other`，无法恢复精确原因。最后一条 503 上传日志与这 6 项不关联，历史 -1004 和正常温度样本也早于本次失败。USB 断开后无线发现未成功，备份索引未复制。见证据目录 `device-diagnosis/REPORT.md`。新代码没有安装到手机；索引上限也不是所有上传管线原件读取数的全局上限。

布局微测量对同一个模型交替执行五组旧路径和新路径，计算四档密度，两边均校验并消费 120 个可见照片的结果。旧路径仍实际构建整库行并扫描，新路径通过拓扑查询。网络、图片解码和 GPU 不在该计时区间。测量受单核 CPU 上的布局构建及遍历限制，不能由此换算 App FPS。

最终源码未附加 profiler 的完整原生回归 `unit-verified-final.xcresult` 中，五组结果如下。

| 工作负载 | 原路径中位数与范围 | 新路径中位数与范围 |
| --- | --- | --- |
| 12,000 张照片、四档密度 | 41.305ms，38.852–46.077ms | 0.0956ms，0.0736–0.0989ms |

另有 120 个缩略图命名空间的交替微测。原路径耗时会随历史凭据绑定数量增长，本轮反复运行测试积累了大量合成绑定，因此不将其数值外推为普通用户延迟。账户确认、绑定变化、令牌轮换、像素/版本隔离及并发更新均有行为回归。

显示回调记录只描述主运行循环回调间隔。模拟器截图、录像及 `CADisplayLink` 均不构成真机 GPU 帧时或 60/120Hz 流畅度结论。旧路径与修复后相同操作均有合格图片起点及实际 UI 验收。

单独构建详情 shell 的测试中，多轮首次冷布局约 0.58–1.12s，随后 120/12,000 张照片均约 125–158ms。这是创建独立测试窗口及 SwiftUI 树的测量，不能作为实际点击延迟或已消除全部冷启动开销的证据。实际 App 控件出现和手势另外通过 UI 验收，真机首帧仍需采样。

## 未完成项与限制

双指缩放及年/月/全部尚未达到“与系统照片完全一致”的验收标准。已实现跟手、多照片、可取消和可见锚点交接，并保留减少动态效果路径。另在同一模拟器导入 80 张带标识照片，加上已有 46 张形成采集时的 126 图 PhotoKit 库；系统 Photos 和 App On Device 的配对曲线未合格，拒绝用于一致性结论。清晰起始端点的 AX 仍显示静态几何差异；横纵 stride 规则不同，不能简单改一个 gutter 值外推其他密度或设备。完整证据见 `photos-reference/RESULT.md`。

详情同步根布局仍有约百毫秒的暖态 CPU 成本，冷打开未证明改善；工具栏桥接已具体定位，仍未消除。32ms 媒体激活的 queue/yield 间隔仅为 wall 时间，不能直接归为 pager 独占 CPU。真实控件、视频操作与关闭/编辑回归通过，不等于该性能问题已解决。

尚未测量真机温度、能耗和长时间后台备份。热控制修复减少了主动准备工作；真实用户每一项备份失败的具体原因仍需该设备失败记录或日志，不能把本轮已复现的本地授权错误推断成全部失败的原因。

仍待实际采样的代码热点包括旧缩略图缓存迁移中的同步磁盘读取，以及 PhotoKit 修改版本的同步验证。本轮不移除这些一致性校验，也不把仅由代码审阅发现的候选项记作已证实的掉帧根因。

精选集封面缓存与请求合并减少重复工作；首次获取仍依赖服务器元数据，不构成首访问零延迟保证。
