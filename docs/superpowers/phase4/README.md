# Imora 第四批方案评审

2026-11-15 · **仅规划，待用户确认；未实施。**

推荐采用“本机持久草稿/预览＋增强服务端保存编辑意图与派生资源”。本机、云端和系统照片分别记录保存结果；原件与备份证明独立保护。

用户追加要求后的二次审计发现17项需要补全的规则，已同步本版。**图片加载是优先阶段4P及G5放行要求：正常完整缓存复访，首个可交互图库内容帧就有全部可见真实缩略图，不逐张加载/淡入；打开/返回不黑屏，不靠延长启动屏掩盖等待。** 首次空缓存/离线/权限等独立定义。当前仅文档完成，速度与UI尚未实测。

## 推荐交付顺序

| 阶段 | 用户结果 |
|---|---|
| **4P，先做** | 首屏真实图片齐备、滚动预取、打开/返回连续；所有图片入口同一G5门槛 |
| 4A | 实况按住/松手、本机可靠分类；可先独立交付 |
| 4B0 | 原件隔离、草稿恢复、版本化保存协议 |
| 4B1 / 4C | 实况封面/修剪/静音/循环/来回；视频裁剪旋转调色 |
| 4D | 云端分类、最近的日子、旅程建议 |
| 4E | 回忆影片播放、节奏、音乐、导出 |
| 4F | 完整待同步、跨设备/PhotoKit冲突与整体验收 |

4P在前三批最终版本上独立实施，与4A一同放行；18任务中的17–18编号仅为追踪，实施优先。4B1与4C共享4B0基础；4D可与编辑器独立推进；4E可先无音乐播放，曲库不阻塞。最终完整离线同步须4F验收后才宣称完成。

## 最需要确认的选择

1. **实况生效范围：** 推荐先完整保存/播放Imora实况编辑，明确导出照片/视频；系统Photos的关键帧/修剪/效果写回须公开API验证通过。普通视频的显式系统写回仍在本批计划内。
2. **同步默认：** 推荐只保存入口来源；已验证配对另选云端同步；冲突保留双方版本，由用户决定，不按时间戳自动覆盖。
3. **旅程：** 推荐保守的“旅程建议”，常驻地区选填，不新增背景定位；证据不足时生成日期地点集合。
4. **回忆导出：** 推荐1080p SDR首版；无音乐/允许导出的内置音乐，不默认接Apple Music；HDR保真单独验收。
5. **顺序：** 按新增要求先4P图片基础，与4A共同放行；再4B0，之后安排实况/视频/聚合/影片，最后4F收口。G5随各新图片入口验证，不拖到最后。

## 图片速度的建议门槛

参考真机上：同进程恢复完整首屏p95≤150ms；完整持久缓存的进程重启p95≤800ms；另测用户启动动作至可操作内容总时长，参考p95≤1.5秒。缓存复访首个图库内容帧真图覆盖100%，打开/返回0空白帧。首次空缓存和缺资源有单独指标与恢复行为，不把灰块/thumbhash计作已加载。全部是未实测的设计目标，详见增补规范第11节。

## 当前未决定为可用的能力

- 系统实况任意关键帧/修剪/loop/bounce完整写回：API与往返验证门槛G2。
- HDR、Log、空间、电影效果、慢动作重定时的保真编辑：profile门槛G3；不能拿普通SDR替代宣称。
- 具体内置音乐：需要可导出权利记录与实际素材；无音乐播放器可先交付。
- 前三批最终接口落点：原会话仍在开发，实施前按对齐清单复核。

本目录里的接口、路径、测试与阈值都是提案。确认本方案不等于授权本会话实施；后续须另行明确授权，再使用独立工作区和测试资源。当前未修改第一至第三批工作树，未安装App、运行模拟器/产品测试、提交或部署。
