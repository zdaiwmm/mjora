# Imora 第四批详细设计（评审稿）

日期：2026-11-15，Asia/Shanghai。状态：**待用户确认；仅规划，未实施。**

本文件与 [接口契约](04-contracts.md)、[分期计划](02-implementation-plan.md)、[验收矩阵](03-acceptance-matrix.md)、[源码依据及对齐清单](05-evidence-and-alignment.md) 一起评审。用户追加图片即时呈现要求后的 [二次审计](06-experience-audit.md) 和 [图片、交互与动效补充规范](07-loading-and-interaction-spec.md) 为本版组成部分，具体新规则优先于旧稿笼统描述。所有新类型、接口、阈值和文案均为本方案建议，不表示现有系统已经支持或用户已经批准。

## 1. 目标、范围与不可破坏的边界

第四批覆盖审查 F10、F12–F15：实况按住/松手、关键帧、修剪、静音、循环和来回播放；视频时间修剪、画面裁剪、翻转、旋转和调色；可靠媒体分类、最近的日子和旅程；回忆自动播放、音乐、节奏和导出；离线编辑草稿、待同步与冲突处理。

追加横向范围：所有图片入口的启动/滚动/打开/返回呈现体验。新增4P与G5，优先于高级编辑交付；正常有合法完整缓存的复访，首个可交互图库内容帧包含全部可见真实缩略图，无逐格加载/淡入。首次无缓存、离线、卸载原资源与权限变化单独定义，不能用长启动等待、错误旧图或全库预加载掩盖问题。具体层级、缓存身份、首屏包、调度、尺寸与可测预算见补充规范第1–5、11–12节。

第一至第三批已批准的日期、来源搜索、收藏重试、照片参数与几何编辑、相册上传告知、图库/精选集布局、筛选和动效仍由原会话负责。第四批只消费其交付，不重复改造。截图分类复用第三批结果，不建立第二套筛选口径。

本轮只写本目录中的规划材料。没有授权改产品代码、创建实施分支、安装 App、启动或操作模拟器、运行测试、提交、合并或部署。后续计划中的命令都是未来实施步骤。

约束如下：

1. iOS 最低版本为 **26.0**，Swift **6.0**；延续 SwiftUI/UIKit、PhotoKit、AVFoundation、Core Image/Metal、现有 NestJS/Kysely/PostgreSQL 与媒体任务队列，不增加第三方编辑 SDK。
2. 本机、云端、经验证配对是三种明确来源。文件名、时间、GPS、视觉相似都不能建立备份配对。
3. **原件、当前渲染版、编辑意图、成品与备份证明是不同对象。** 编辑、导出成功不能增加删除本机原件的资格。
4. 每次保存先持久化意图；网络未知结果先对账；界面不得用“已同步”代替“已保存到此设备”。
5. 自动聚合不是云端相册，不自动上传本机照片；用户主动转换为 App 相册时才复用前三批的明确备份流程。
6. 第四批不引入自动删除、自动覆盖另一端、背景定位、Apple Photos 私有数据库/私有 API、Apple Music 曲库导出、长曝光效果、变速编辑、多轨剪辑、生成式回忆或云端人脸训练。
7. 普通视频与支持的 SDR 媒体先完整交付。HDR 保真、空间/电影效果/慢动作重定时保真、系统实况完整写回必须各自通过验证门槛；不能因普通视频可播放就宣称这些能力成立。

## 2. 现状与推荐架构

### 2.1 已确认的现状

| 模块 | 只读源码观察 | 对第四批的影响 |
|---|---|---|
| 实况查看 | `LivePhotoPage` 在长按 0.35 秒后切换播放，没有抬手停止；共用 `VideoPlayback` | 改为手势状态机，不能简单再调用一次 toggle |
| 运动缓存 | `LocalImageLoader.motionFile` 以本机 ID 命名，优先当前 full-size paired video | 新缓存必须包含内容修订，防止编辑后继续播放旧片段 |
| 视频 | `VideoTrimEditor` 依赖 `/assets/{id}/trim`，原片至少 2 秒，保留至少 1 秒 | 新契约与遗留接口分别处理，不能把旧服务器误识别为新编辑器 |
| 服务端编辑 | 当前读到的 `AssetService.editAsset` 限于静态图，明确拒绝 Live Photo；未见此树中的 trim 路由 | 新增实况/视频文档与渲染链路，不直接把 `photo` action 当视频接口 |
| 回忆 | `MemoryLane.openMemory` 进入普通查看器；服务器 memories 是素材集合 | 集合与影片项目分离，兼容旧回忆，不扩写旧 MemoryType 枚举 |
| 离线 | 有 SQLite 增量索引、缓存、备份意图日志；不是编辑 outbox | 单独建编辑事务存储，不能把浏览索引 reset 当作清空草稿 |
| 备份 | `primaryResource`/`motionResource` 优先 full-size 当前资源；`BackupProof` 与 local revision 绑定 | “已验证当前资源”不能直接升级为“未调整原件已备份” |

这些是读取时的工作树事实。前三批正在变化，不能用 HEAD 号代表全部未提交内容，实施前必须重读对齐清单。

### 2.2 比较过的路线

| 路线 | 收益 | 代价与适用范围 |
|---|---|---|
| A. 全部由本机导出并上传成品 | 离线直接，服务器改动少 | 难以跨设备继续编辑；成品与原件混淆风险高；旧服务器只能作为明确的副本上传目标 |
| **B. 本机预览/草稿＋增强服务端意图与成品（推荐）** | 离线可用；可对账、可恢复；能保留原件与编辑链；各阶段可独立开放 | 需要新文档、版本检查和渲染任务；系统相册写回须单独验收 |
| C. 全部服务端渲染、在线才编辑 | 客户端渲染实现较少 | 每次操作依赖网络，无法满足离线编辑；不推荐 |

选择 B 是方案作者建议，**尚未取得用户确认**。分布式保存不可能把 PhotoKit、App SQLite 和服务端放进一个数据库事务；设计明确保存各目标结果，不许伪造全局回滚。

### 2.3 保存的实际含义

| 入口/动作 | 默认结果 | 其他目标 |
|---|---|---|
| 本机实况高级编辑 | “保存到 Imora”，账号绑定的本机编辑意图与预览 | “同步云端编辑”需验证配对且用户明确选择；“导出视频”另建成品；系统实况完整写回经门槛 G2 后才可增加 |
| 本机普通 SDR 视频编辑 | 先保存 Imora 草稿；完成后默认保存 Imora 版本 | “应用到系统照片”是显式动作，使用 PhotoKit 内容编辑输出；此能力属于 4C 验收，不是永久排除 |
| 云端实况/视频 | 保存云端编辑意图；离线时“已保存到此设备，待同步” | 没有本机 PhotoKit 写权限也能编辑有权限的云端资产 |
| 已验证配对 | 跟随本次编辑入口，默认只保存该来源 | 提供“同时同步到云端”，按账号记住选择且随时可关闭；没有明确意图不得自动上传本机原件 |
| 导出/保存副本 | 新文件或新的 PhotoKit asset，原资产不变 | 单独取得导出/添加权限；没有把导出副本配成原资产备份的副作用 |

本机高级实况效果在第一版只承诺在 Imora 中保留和播放。系统 Photos 中是否出现同样封面、裁剪和效果，是独立能力。Apple 的 `PHLivePhotoEditingContext` 提供帧处理与音量，但 `photoTime` 是只读，不能据此承诺任意关键帧/时间区间写回。[Apple 实况编辑上下文](https://developer.apple.com/documentation/photos/phlivephotoeditingcontext)、[photoTime](https://developer.apple.com/documentation/photos/phlivephotoeditingcontext/phototime)。

系统相册不支持某一操作时直接显示“此效果已保存在 Imora；可导出为视频”。不得把静态图或普通视频静默替代为一张实况照片。若用户希望“全部实况高级编辑必须同步出现在系统照片”，须选择 G2 的完整写回路线后再确定该交付时间。

## 3. 共同数据模型与资源保护

### 3.1 身份与修订

- `AccountScope = (serverIdentity, accountID)`，复用现有 `SyncScope.accountKey` 语义；不以 LAN/WAN URL 或登录 token 做永久命名空间。
- `EditSubject` 为 `local(installationID, localIdentifier)` 或 `remote(assetID)`。已验证配对是显式关系，不合并二者的内容修订。
- `SourceManifest` 记录来源资源角色、各自内容摘要、字节数、原始尺寸、方向、时间基、色彩信息、配对组件 ID、读取时权限范围；未知字段明确 unknown。
- `sourceRevision` 变化代表编辑输入变化；`editRevision` 是云端编辑文档的单调版本；`renderRevision` 指对应哪个 editRevision 生成的成品。不能用 `updatedAt` 或缩略图 hash 代替。
- 本机 `modificationDate` 只用于触发重新检查；内容指纹和调整数据摘要才决定可否重放同一编辑。收藏变化不应迫使用户丢弃颜色草稿。
- 缓存键：`account/subject/sourceRevision/editRevision/renderProfile`；本机运动缓存另含 PhotoKit adjustment digest。原件新修订不复用旧文件。

### 3.2 五类资源

| 类别 | 可否重建/淘汰 | 能否作为原件删除证明 |
|---|---|---|
| unadjusted original | 不允许被编辑器覆盖 | 只有具体角色、摘要、owner、配对和字节回读全满足才可能参与证明 |
| foreign/current baseline | 不理解的外部编辑所提供的当前版；作为本次固定输入 | 不得冒充未调整原件 |
| edit document/draft | 用户劳动，必须持久化；显式放弃才可删 | 否 |
| preview/render | 可重建的预览与派生成品，标出源修订与渲染版本 | 否 |
| backup proof | 现有独立体系管理，严格记录验证范围 | 不能由以上四者反推或补造 |

基线保护门槛 G0：在前三批交付后，核对上传实际字节与 `BackupProof` 能证明的资源角色。遗留 proof 导入为 `legacyCurrentOrUnknown`，保留历史，不自动升级。对新增或修改后的资产，无法证明所需原始照片/视频及实况双方完整可读时，第四批相关编辑不得让它进入清理候选。既有与第四批无关的清理逻辑是否需要调整由原会话对齐，不能在本规划会话修改。

本机高级编辑若依赖 pinned baseline，活跃草稿持有租约，缓存清理不准删。`SourceManifest` 中的源仍在系统图库或服务器时可按权限重新读取；离线副本若是唯一可继续编辑输入，按用户数据保护，不能归类为临时缓存。显式清空离线数据需列出受影响草稿并保留意图或由用户放弃。

### 3.3 外部编辑与恢复原始

能解码当前 Imora adjustment 的版本才返回“可处理”；不能解码外部/未来版本时，使用固定的当前渲染版作为新的输入，完整保存它的来源说明，不伪称能重建外部参数。视频的 PhotoKit 版本行为与静态图不同，Apple 明确说明无法读取视频调整数据时须处理当前版。[Apple 内容编辑](https://developer.apple.com/documentation/photokit/editing-asset-content)。

三个动作必须分开：

- 撤销/重做：本次编辑的完整快照，包括帧、区间、效果、静音、几何、颜色。
- “还原 Imora 编辑”：新建中性文档修订，回到本次受支持基线；同样需要 CAS。
- “还原系统原始版本”：仅在 PhotoKit 支持且用户明确选择时触发，不能借撤销 Imora 编辑删除外部编辑。无法取得完整原件时保留草稿并解释原因。

## 4. 实况按住与松手

### 4.1 观看交互

静止时显示当前封面和轻量 LIVE 标记。普通点击只切换查看器工具；长按达到 **0.35 秒**、移动不超过 **10pt** 且当前页面缩放在基准比例时进入播放。保留现有阈值作为首版值，之后只用真机可用性证据调整。

状态：`rest → arming → loadingHeld/playingHeld → rest`。每次按住有独立 `gestureToken`。抬手、系统取消、第二指加入、翻页、缩放开始、下拉关闭、切换账号、离开前台都会失效该 token，并停止播放、回到封面。加载晚到必须核对 token、资产 ID、页面 generation 后才可开始；用户已松手就只允许安全缓存，不能突然播音。

- 0.35 秒前抬手：普通轻点；在识别前移动超过 10pt：让横翻/纵向关闭手势获胜。
- 已开始播放后移动超过 10pt：取消本次 hold，并交还导航；不能因一个 recognizer 永久阻断翻页。
- 双指缩放和图像已放大时的拖动优先；编辑器中的“按住看原图”不触发实况播放。
- 播放到尾时恢复封面，仍按着也不反复重启；须下一次按住。仅当编辑效果明确为循环/来回且用户主动启动时才循环，松手同样停止。
- 远程/已卸载 iCloud 组件：首次需要下载时出现内联加载与取消；沿用账号网络政策，未获蜂窝下载许可则显示“使用 Wi-Fi 或允许此次下载”。不得把数据请求失败当作普通静态图成功。
- 查看器默认静音；临时扬声器开关只影响观看。本次编辑的 `muted` 是成品语义，两者不能混写。
- 保留无障碍“播放实况/停止”操作，按钮可以持续播放并明确状态；VoiceOver 用户无需持续按住。它与 hold 共用一个播放 owner，不能双重播放。
- 平时不常驻逐帧控制；在编辑的关键帧页提供，原有定位能力不丢失。

### 4.2 数据、权限与恢复

只读取当前合法来源：本机 PhotoKit、经验证的配对视频或有权读取的云端 motion asset。不为播放新建云端资产，不修改 `livePhotoVideoId`。只获取屏幕可见的一项，翻页取消任务。拒绝照片权限后本机播放停止；有授权的云端资产可继续。

缺运动组件：显示“实况视频不可用”，仍保留照片查看和原有配对证据；可重试但不自动修复到不同视频。音频中断/耳机断开/进入后台立即暂停，不自动恢复声音。Reduced Motion 不自动播放，手动播放仍可用。

## 5. 实况编辑

### 5.1 编辑器结构与行为

延续前三批编辑器工具栏、撤销/重做、完成/取消、原图比较；增加“实况”页。底部缩略帧带有起止手柄与封面标记，工具为声音与效果。关键帧滑动先预览，点“设为封面”才提交一次 undo 节点；拖动区间在松手时形成一次节点，不能每帧占一次撤销。

所有编辑入口区分entryBaseline、自动落盘workingDraft和用户完成后committedDisplay。取消/返回只退出并保留恢复草稿，不入队/不发布、不改变普通图库已完成版本；完成才形成选定目标的提交。已发送操作不能靠关闭编辑器撤销，按receipt对账。密集时间轴、双击/hold/翻页仲裁、crop边界和奇数输出、safe-area/iPad/RTL/VoiceOver与动效交接均执行补充规范第6–7、10节。

| 项目 | 确定的建议规则 |
|---|---|
| 时间 | 保存原运动视频 presentation timeline 的有理数时间，不用显示用的 Double 或 30fps 假设；区间 `[in,out)` |
| 最短范围 | 至少连续 **3 个实际可解码帧且时长 ≥0.3 秒**；原片达不到时仍可观看和静音，关闭修剪/循环/来回并说明 |
| 关键帧 | 对齐实际可解码帧 PTS，必须落在保留范围内；裁掉关键帧时在手柄松手后移到最近保留帧，给出可撤销提示 |
| 封面来源 | 默认原始照片；用户设置关键帧后才以运动视频该帧生成封面；说明视频帧分辨率可能低于原照片，不覆盖高分辨率原照 |
| 静音 | 普通实况可保存开/关；没有音轨时显示“无声音”，不显示可操作但无效的按钮 |
| 普通 | 按住播放选中片段，松手回所选封面 |
| 循环 | 只循环 `[in,out)`；首版直接拼接，不声称做了无缝补帧；若有明显接缝仍忠实预览；成品无音轨 |
| 来回 | 按实际帧序列正向后反向，反向不重复首尾端点；成品无音轨，防止反向人声 |

切换循环/来回时保留用户普通模式的声音偏好，但当前效果强制静音；切回普通恢复该偏好。帧序列 A/B/C/D 的一次来回周期为 A/B/C/D/C/B，再从 A 开始。PTS 根据输出帧的实际时长重建，不能依赖 AVPlayer 的负播放 rate。

最短范围是**改变修剪区间**的校验：完整未修剪范围 `in=0,out=原duration` 可保存普通模式的静音/受支持颜色几何，即使源本身不足3帧或0.3秒。短源不能借此开启loop/bounce；文档验证与UI使用同一规则。视频同理，完整原范围可保存旋转/调色，只有实际修剪才要求2帧且0.1秒。

普通实况的原始照片封面与运动视频画幅/稳定处理可能不同。保留原照作为单独 poster，切换播放不缩放整张查看器；手动视频关键帧使用轨道显示变换得到的实际画幅。不将某一帧直接替代 primary original。

### 5.2 存储和导出

`LiveEditV1` 保存范围、封面模式/PTS、muted、effect、源组件修订；可继承前三批已验证的照片参数，但必须明确同一几何/颜色是否同时应用到静止与运动两部分，不能只调静态封面。首版若共享渲染尚未通过夹具验证，就保留实况页并关闭该实况的颜色页，不假装两个部分一致。

Imora 内的实况保存是一个逻辑文档＋poster rendition＋motion rendition，资源 ID 和原始配对保持不变。服务器原 motion asset 不是用于接收客户端覆盖上传的地址。服务端先接受文档，后台按修订生成两个派生资源，全部校验通过才一次切换当前展示引用。

首版是否开放Live颜色/几何的技术规则已确定：每个组件都记录独立尺寸、transform/clean aperture和color profile；crop以原照显示坐标归一化映射到motion，具体取整见契约。颜色在双方都能证明支持的SDR profile下统一运算，任一组件unknown/HDR且无已验证转换就关闭整项Live颜色；几何元数据不明则关闭Live几何。它们属于可独立验证的子能力，不是只调poster的降级；Live核心封面/修剪/静音/效果不因此被阻塞。

导出选项：

1. “导出照片”：所选封面独立 JPEG/HEIF，清楚标为照片。
2. “导出视频”：普通效果导出一个保留范围；循环/来回导出完整周期的最小重复次数，使总长达到 **3 秒**，总长不超过 **30 秒**，没有音轨；可预览实际时长。若单个周期本身已超过30秒，要求缩短选区，不截断周期伪称完整循环。
3. “保存实况副本到系统照片”：只在 G2 对关键帧、修剪、方向、音频、配对元数据、重开编辑和重启/跨设备传输全部通过后提供。不得使用私有 MakerApple key 或未公开写法作为默认依赖。

首版不把任意 loop/bounce 当成 Apple Photos 系统效果。若 G2 无法使用公开 API 实现，保持 Imora 效果和明确的视频导出，作为公开限制交由用户确认，不偷偷延期承诺。

### 5.3 失败与兼容性

源双方缺失、权限不一致、编辑前后 motion 配对变化都阻止云端提交，保留本机草稿。渲染一方失败时旧成品继续可用，新文档显示“已保存，生成失败”；重试同一修订，不写假回滚。旧服务器可做本机草稿/预览/明确副本导出，不允许将参数丢到 `other` 再发送给不支持的 API。

## 6. 视频编辑

### 6.1 工具与顺序

视频编辑器含“视频/调整/裁剪”，使用同一份完整草稿。视频页含时间修剪与静音；调整页复用前三批曝光、对比度、饱和度、反相、高光、阴影、亮度、黑点、暖色、色调的取值与公式；裁剪页含自由/原比例/1:1/4:3/16:9、镜像和 90°旋转。第一版不新增照片设计之外的透视算法；如前三批校正/透视内核可用于逐帧并通过性能门槛，可按同公式开放，否则该视频页明确只提供已验证工具。

管线顺序：选定原始时间范围 → 按轨道 transform 校正方向和 clean aperture → 原始显示坐标裁剪 → 镜像 → 四分之一转 → 支持的校正 → 颜色 → 统一编码。几何遵循前三批“原始已校正方向像素”语义；不得因视频编码宽高与显示宽高不同二次旋转。

- 新接口支持至少一个可解码帧的普通视频；修剪后至少 **2 个实际帧且 ≥0.1 秒**。原片不足最短修剪范围时禁用修剪，仍可旋转和调色。旧 `/trim` 继续沿用 2 秒/1 秒限制，文案明确。
- 起止点对齐解码帧时间，时间轴仍显示原视频时间；音频裁切采用同一时间零点，最终 A/V 漂移目标 ≤**40ms**。
- 90°转后裁剪比例按输出方向解释；用户设置的裁剪区域必须映射回原始显示坐标，重开不跳框。
- 原图比较暂停在同一 PTS，以同样显示几何比较；离开比较回到完整草稿。所有工具共享撤销/重做。
- 音量只设静音，不加入多轨/配音；没有音轨合法。

### 6.2 色彩和性能

普通 SDR：输入按色彩标记转换到非线性 sRGB 运算域，复用前三批精确色彩顺序与夹取，再输出标记为 Rec.709 的 SDR 视频。色彩转换必须显式定义 transfer/range/matrix，不只是替换 ICC 标签。预览与云端/本机导出的固定色块，8bit RGB 比较目标平均通道误差 ≤**2/255**、最大 ≤**6/255**（排除编码边缘，使用统一解码参考）；参数/顺序必须完全相同。

HDR/P3/Log/空间/电影效果素材先识别 profile。默认保留原片观看与草稿，不把 8bit 管线偷偷接入。对于 HDR：可提供明确选择的“转换为 SDR 副本”，在预览前显示输出选择；真正 HDR 编辑仅在 G3 证明动态范围、色彩标记、解码器与设备匹配后开放。Apple 的 AVFoundation 支持 HDR 编辑与播放，但这不等于当前 Imora 自定义滤镜天然保真。[Apple HDR 示例](https://developer.apple.com/documentation/avfoundation/editing-and-playing-hdr-video)。

首版成品配置：MP4/H.264、8bit yuv420p、Rec.709、AAC 48kHz（有音轨且未静音时），分辨率不高于原始输出，最长边默认 **1920px**，30fps 上限但不把 24/25fps 提升到 30；VFR 输出按输入 PTS 保持时序，必要降采样不改变播放总长。原画质/HDR 配置须单列验收。内部视频编辑当前展示可用更高质量配置，不能把“1080p 分享副本”的限制混写到原件尺寸字段。

交互预览使用 GPU、限尺寸缓存和最新意图覆盖队列，滑块停止后渲染最后值，禁止在主线程全片重编码。4K 长视频不全量解码到内存；后台/热限制时暂停或降级预览并说明，完成后可继续。首版渲染并发每设备 1 项，每账号服务端默认 1 项、全局默认 2 项，可由管理配置调整；测试门槛见验收矩阵。

### 6.3 系统照片写回与权限

在支持的普通视频上，用户点“应用到系统照片”后：固定编辑输入 → 校验当前 PhotoKit 修订 → 渲染到 `PHContentEditingOutput` → 附带版本化 `PHAdjustmentData` → `performChanges` → 回读受支持的调整数据与源身份。输出失败保留 Imora 草稿，不声称系统已保存。库变更操作仍以系统最终许可结果为准。

不能理解原有视频 adjustment 时，Apple 可能只提供当前版，不能保证原编辑链可以回调；界面说明“在当前系统版本上继续编辑”，本次只还原 Imora 新增部分。保护 G0 所需未调整原件证据另算。

## 7. 可靠媒体分类

分类是一组带来源的事实，不是互斥枚举；一项可以同时为视频、屏幕录制和已编辑。每个事实取 `yes/no/unknown`，并保存 `evidenceType + evidenceRevision + extractorVersion`。来源未覆盖时不显示 0，显示“尚未分析/仅本机可识别”。

| 类别 | 本机可靠依据 | 云端依据及限制 |
|---|---|---|
| 照片/视频/实况 | PHAsset mediaType、photoLive；验证配对不改变媒体本身身份 | 服务端类型与合法 livePhotoVideoId；缺失配对标示异常 |
| 截图 | photoScreenshot，复用前三批 | 现有服务端明确字段或经配对验证后显式同步的 PhotoKit 事实；文件名前缀不能独立确证 |
| 全景 | photoPanorama | 原文件可信元数据；宽高比只作“可能”，不进入可靠分类计数 |
| 自拍 | PhotoKit `smartAlbumSelfPortraits` 在可访问资产中的成员 | 明确导入的受支持事实；不以识别人脸或相机前置猜测确定分类 |
| 高帧率/慢动作 | videoHighFrameRate 可确证“高帧率”；慢动作需额外可读取的重定时证据 | fps 高不能直接等于慢动作；证据不足只列高帧率，不提供假慢动作入口 |
| 延时摄影 | videoTimelapse | 可验证原始元数据；视频短或拍摄间隔猜测不算 |
| 屏幕录制 | 当前 SDK/OS 可用的 videoScreenRecording | 明确的原文件/导入事实；OS 无此 subtype 时 unknown，不用版本号硬猜 |
| RAW/连拍 | UTType 原始资源、burstIdentifier | 原文件受支持标记；连拍分组可与现有 stack 并存，不能把 stack 当真实 burst |

公开 subtype 是 OptionSet；自拍使用智能相簿成员，不能凭空定义 `photoSelfPortrait` subtype。[Apple subtype](https://developer.apple.com/documentation/photos/phassetmediasubtype)、[自拍智能相簿](https://developer.apple.com/documentation/photos/phassetcollectionsubtype/smartalbumselfportraits)。

`DeviceMediaFacts` 独立于备份 `DeviceAsset` 快照，避免分类字段变化造成 proof 版本连锁失效。分类提取只读元数据，不触发原片下载/重新上传。有限照片授权只统计可访问资产，顶部显示“仅所选照片”；完整库计数不能由有限样本推断。

精选集增加“媒体类型”，沿用前三批大/小/无预览、固定、排序和折叠。零已知项可以不展示；数据源不支持的分类不展示为可点击空壳。点击进入复用现有网格、来源标签和选择流程。计数、筛选结果与分页都使用同一 snapshot/facts revision；Live motion 子资产不重复计入视频数量。

云端分类由服务端可验证提取为主；用户同意“同步媒体类型”后可上传白名单事实，服务端验证 owner、原件摘要/配对和 extractor 版本，记录为 PhotoKit 导入来源，不能冒充服务端从文件推导的事实。不上传本机 identifier、相簿名称或任意 EXIF blob。

## 8. 最近的日子与旅程

### 8.1 共同规则

本机与云端各自聚合，各自显示来源。已验证配对在混合展示时仅呈现一次；默认不建立混合源的云端集合。本机运行元数据聚合，增强服务器提供云端聚合与分页，不读取 Apple Photos 内部精选结果。

默认排除 trash/hidden/locked/archive、截图/屏幕录制、实况 motion 子资产；不把“已备份”作为入选条件。连拍/重复仅使用现有可靠分组，每组优先收藏、再最大可用像素、再时间/ID；不引入人脸或主观质量模型。

所有聚合保存 `algorithmVersion`、输入 snapshot、时间依据、素材成员、封面选择和用户覆盖。不改变照片原时间/GPS。用户改标题、封面、隐藏、排除素材、合并/拆分形成覆盖层，重建不得擦掉。自动规则变化只更新未锁定生成结果；已保存项目固定成员顺序。

### 8.2 最近的日子 V1

- 按前三批摄影者本地墙上日期分组，默认展示最近 **30 个自然日**的非空日期；今天/昨天由设备当前时区界定，资产所属日期仍按已存 capture wall-clock 口径，两个概念明确区分。
- 日期页至少 1 项也可打开；首页卡片至少 **3 个可见逻辑资产**，不满足时只在按日期列表中出现，避免空洞卡片。
- 每日卡片预览最多 **12 项**，详情包含该日全部符合条件资产并分页；卡片写“共 N 项”，不把 12 写成总数。
- 封面按收藏、已编辑且可用成品、像素、时间/ID 稳定排序；不把云端不可读/已隐藏素材选封面。
- 不把上传日当拍摄日；只有上传日可用时归“日期未知”，不自动塞进今天。晚同步素材加入它真实所属日期。
- 点击卡片进入该日网格，可从“播放回忆”显式生成影片项目；不一进入详情就响音乐。

### 8.3 旅程 V1：先给可解释的候选

旅程不能仅由两个 GPS 点可靠证明，首版称“旅程建议”。不请求常驻/实时定位，不推断家庭住址。用户可选设“常驻地区”（本机保存粗粒度中心＋半径 **50km**；云端计算须单独同意同步这一地区），也可不设。

有常驻地区时：

1. 用素材现有捕获 UTC 时间排序；捕获绝对时间 unknown 的资产不参与自动时间距离推断。
2. 可信坐标位于常驻地区 **100km** 之外才作为 away seed；定位精度已知且劣于 **10km** 的点不作 seed。
3. 相邻 away seed 间隔 **≤48 小时**可连段；间隔 **>48 小时**拆分。中间出现常驻地区内可信拍摄点也拆分。跨度 **>30 天**按最大的时间空隙拆分，无空隙时仅做月份地点集合，不称旅程。
4. 至少 **6 个带可信定位的逻辑资产**、跨度 **≥24 小时**且跨越 **2 个当地日期**才生成旅程建议。较短活动只进入日子；这些阈值是保守的产品建议，不是客观旅行定义。
5. 旅程时间窗内无坐标但时间可靠的素材默认放到“可能属于此旅程”，不自动加入，避免混入他人照片；用户确认才进入固定成员。

未设常驻地区：按 48 小时时间断点和半径 **50km** 地点簇生成“地点与日期”集合，**不标为离家旅程**。用户可以选中任意素材手动建立旅程，确认标题/日期/成员，不要求位置授权。

跨时区日期标签采用各素材已有时间依据；归并判断只用可靠绝对时间，不能把 DST 重复的墙上时间强行当成唯一时间。纯 wall-clock 数据仍可归日，旅程自动判断标为不足。反向地理编码优先已有 city/country；缺失时用“地点未命名”，无需发起位置服务。用户主动“查找地名”才说明外部服务和坐标发送。

旅程内容页显示日期、粗粒度地点、来源、成员数与“为何推荐”；允许排除、加入、重命名、固定和转相册。地图只有已有可信坐标才出现。无限定位、精确住址标题、自动跨账号拼接都不在范围。

## 9. 回忆影片

### 9.1 集合、项目与播放

已有 `Memory` 继续表示集合，保留保存/移除语义；新增 `MemoryMovieProject` 表示可编辑影片。旧 Memory 点击后进入电影播放器，播放器的“全部照片”仍可回到原查看器；它不修改旧 Memory 的素材和类型。

项目第一次播放才编排，写入版本化 manifest：素材 ID/来源/源与编辑修订、顺序、每项区间/时长、fit、过渡、标题、音轨与节拍网格、总时长、输出 profile。自动编排采用稳定随机种子/排序，重开不随机重排。编辑素材先固定本次 revision，观看中后台新成品不突然改变影片。

首版预设：舒缓 **60 BPM**（每张 4 拍，4 秒）、标准 **90 BPM**（4 拍，8/3 秒）、轻快 **120 BPM**（4 拍，2 秒）。视频片段保留 **2–5 秒**并按拍点对齐；实况作为 2–3 秒运动片段，不支持时使用封面并明确计入“静态显示”。自动项目默认目标 **30 秒**，最多 **30 个素材**；标题最多 2 秒，之后顺序选入直到达到目标附近的完整拍点。用户可选 15/30/60 秒，最多 **60 个素材、180 秒**。

首版自动选片算法：按拍摄时刻/稳定ID排序，将候选等分为目标数量的连续时间序列桶，每桶依收藏、可用像素、时间/ID选一项，选中后仍按时间播放。目标数量为最接近 `(目标秒数−标题秒数)/四拍秒数` 的整数，最少1、自动最多30且不超过候选数；同样接近时取较小值。短于2秒的视频/实况可用封面静态显示，不能伪造2秒有效运动。用户自选顺序直接保留，不再分桶。暂不使用人脸/模糊评分挑选素材。

拍点指相邻素材开始的间隔，过渡的200ms属于相邻画面的重叠，不额外吃掉四拍间隔。渲染计划为前一项增加需要的重叠区间，最终总长按manifest减去overlap计算；原片没有足够片段可供重叠时该处改为直接切换。影片片段的in/out属于所引用editRevision的展示时间轴（修剪后的起点为0），不是重新解释原始未裁剪时间。

总长计算包含所有过渡重叠；短素材不足目标时忠实缩短，不复制照片凑长，不裁成空片。用户固定素材不因自动取舍悄悄删除，超过限制时让用户缩短选择或拆成两个项目。

首版图片默认 contain，使用中性背景；可显式选择 fill/crop，不自动裁掉头部。使用 200ms 淡入淡出，无随机 Ken Burns/复杂缩放；Reduced Motion 关闭平移缩放并使用简单淡变或直接切换。自动播放由用户点击卡片触发，默认音乐静音，显式开声；进入后台、音频中断、退出、账号切换立即停。

控制包括播放/暂停、前后素材、进度、声音、“全部照片”、节奏、音乐和导出。单击显隐，VoiceOver 有具名操作，长标题与动态字体不遮挡照片。播放计时跟随 media clock，不使用每张独立 Timer 累积漂移。

### 9.2 音乐与原声

- 默认“无音乐”；只有权利清楚、允许随视频导出的内置曲目才列入可导出目录，保存 trackID/version/digest/BPM/beatOffset/rightsProfile。
- 具体曲目需后续提供可核验资产与授权记录；这是内容采购门槛，不影响无音乐播放器先独立交付。没有曲目时不放置虚假的音乐选项。
- 第一版不接 Apple Music、不下载网络歌曲，也不宣称订阅音乐可嵌入导出。用户文件导入可后续作为可选增强，单独校验 DRM 与可读取性。
- 视频原声默认关闭；用户打开后，音乐在有原声片段期间降到线性音量 **0.2**，片段前后 **150ms**平滑。静音实况/循环/来回不恢复原声。无音乐时原声线性音量 1.0，最终混音不得削波。
- 音乐不够长只在目录中标明的可循环边界重复，并用 **500ms**交叉淡化；否则到结尾淡出，不随便改变速度/BPM。
- 为保持首版60/90/120 BPM和音乐拍点一致，音乐目录仅展示与当前节奏精确匹配、beatOffset已校验的曲目。更改节奏使曲目不匹配时先提示，用户确认后切为无音乐并重编排；不暗中变速或保留错位音轨。将来支持任意BPM需另版planner契约。

### 9.3 加载、导出与隐私

进入播放器先准备当前与下一项，不全量下载。下一项/音轨不足时从过渡边界立即冻结统一media clock、进度、音乐与原声并保持有效画面，**3秒**才显示恢复操作；不得先黑屏或让音乐继续。重试从冻结时间恢复；“本次跳过”只修改临时播放路径，不改manifest，导出前明确说明差异。完整规则、item级framingV1、临时静音/导出音轨及操作命名见补充规范第8节。导出前统一preflight，列出缺失/无权/只有低清缓存/音乐不可导出的具体素材，由用户选择下载原件、改用可用清晰度或排除；不默认悄悄跳过。

首版本机导出：1080p、SDR H.264/AAC MP4，横版/竖版以项目选择确定，音频 48kHz；项目含 HDR 时需明确选择 SDR 转换并预览。导出结果与播放器读取同一 manifest；进度、取消、重试与剩余空间在“导出”页显示。内存不持有全片帧；渲染失败仅删除不完整 staging 文件。

完整成品导出完成、可解码并校验时长后原子移到持久结果区。导出中杀进程不承诺帧级续传，重启可从已保存 manifest 重新生成。系统后台执行时间不保证；过期显示“已暂停，打开 App 继续”。“存储到照片”仅在用户明确动作后请求相应添加权限；分享链接是另一步，不自动公开。

云端项目只引用已存在且当前用户可读的云端资产；本机混合项目先只保存在本机，不能为分享项目偷偷上传本机照片。服务器影片导出为后续独立增强，未在 `memoryMovieExportV1` 开放前本机完成，不让服务器接受文件 URL 任意抓取。

### 9.4 固定旧版本与保存项目的保证

影片读取immutable media snapshot，不只记一个可能过期的缩略图URL。增强服务器保留新media-edit的不可变revision与source refs，提供按snapshot/旧revision读取。静态照片即使仍用前三批`/edits`，也在创建snapshot时捕获完整intent及输入、固定对应成品；无法重建的外部编辑固定为当前成品，不发明一个photo editRevision。

**本机/混合项目采用本机持久固定成品，云端项目采用服务端引用租约。** 两者明确分开：

- 自动播放生成的是已落盘的项目草稿，先准备当前与下一项，不下载全片。尚未取得的旧素材若已过期/变更，停在“固定版本不可用”，让用户重新选择/刷新，不静默读取最新版本。
- 用户点“保存回忆到此设备/离线保留”时，预检并将全部所需固定成品（包括远程素材、音轨）放入受保护的项目资源区。全部完成才显示“已保存，可离线播放”；中途为preparing，不能冒称offlineReady。它不在服务器登记本机/混合项目成员或租约，也不上传本机素材。
- 本机已保存项目只依赖持久本机成品，因此服务端30天未引用资源清理不会使它失效；清空离线数据前需列出项目，由用户决定删除保留文件或保持项目可用。照片库/服务器之后改变不会替换这些已固定画面；重新编辑源参数需重新取得源和权限，不承诺只有成品也能恢复原编辑链。
- 保存云端项目时，在同一事务登记其remote snapshot引用；引用存续期间保留旧intent、必要源版本与成品，不能30天自动删除。项目删除/改成员才释放引用；原素材被删除或撤权时即使有物理文件也禁止继续读取，项目进入needsAttention，不复活素材。
- 普通未引用旧snapshot/成品可在30天后清理，GET返回410。旧服务器没有历史版本读取时，保存到此设备必须先下载并验证全部内容，无法固定的项列出问题；未完成项目保留草稿，绝不能拿最新内容冒充旧版本。

保存项目的“固定版本”与“可再次参数编辑”是两个承诺。用户导出MP4后项目和引用仍保留；只有显式删除项目才按相应策略释放，不因导出成功销毁编辑劳动。

## 10. 离线草稿、待同步和冲突

### 10.1 持久化与入口

独立 `editing.sqlite`（WAL，事务，版本迁移，文件保护）保存 drafts、immutable operations、per-target receipts、source leases、render jobs。不把现有 `incremental-sync.sqlite` 或可淘汰 TimelineCache 用作用户草稿仓库。

修改停止 **300ms**后事务写入；按完成/离开/进入后台前必须 flush。300ms 是自动保存目标，不承诺操作系统强杀前未落盘的瞬间值可恢复；“已保存”只在成功落盘后出现。低空间写入失败不能关闭编辑器、清空 undo 或显示成功。

保存前显示目标：“仅保存在 Imora / 同步云端 / 应用到系统照片（可用时）”。未下载完整输入也可保存已有参数草稿，但不能用缩略图伪造原片编辑或成品。精选集增加安静的“编辑草稿”入口，分为草稿、待同步、需要处理和生成中；图库只标异常，正常每格不加图标。

### 10.2 状态与重试

编辑操作状态：`draft → queued → sending → accepted → rendering → ready`。

分支状态：`blockedSource / blockedPermission / blockedCapability / paused / conflict / outcomeUnknown / failedRetryable / failedPermanent`。PhotoKit 目标另有 `localApplied`，云端目标另有 receipt，界面可同时显示“系统照片已保存；云端待处理”。应用层不把它们简化为一个 Bool。

1. 入队事务固定 operationID、规范化 payload hash、baseRevision、源摘要、用户目标与账号；后续编辑创建新 draft/operation，不修改已经发送的请求。
2. 同一 subject、同一目标串行；不同 subject 可并行。只合并从未发送的连续意图；已发送的超时操作不能被“最后值”覆盖后遗忘。
3. 断线/超时/5xx：先查 operation receipt；未知后可用同一 operationID、完全相同请求重试。建议自动间隔 **2/5/15/60/300 秒**后每 300 秒，加入 ±20% jitter；401 暂停等待重新登录，403/422/源改变不盲重试，429 尊重 Retry-After。
4. 关闭自动同步或用户暂停形成持久屏障；后台任务结束不能把暂停误判为用户取消。切回原账号可显式恢复；其他账号完全看不到其草稿、媒体和请求。
5. 服务端已接收不等于渲染就绪。等事件时核对 operationID/editRevision；事件丢失以 GET 对账。旧渲染任务晚到不能覆盖更新修订。
6. 登录会话失效时只冻结任务；登出默认保留受账号隔离的草稿，但隐藏内容、停止任务并释放临时授权，提供显式删除。草稿文件不是跨安装备份；卸载 App 会丢本机草稿，须在导出/账号退出说明中如实表达。

### 10.3 乐观并发与冲突交互

云端完整替换必须要求强 ETag/`If-Match` 和幂等键。初始无编辑也有 revision 0 的中性文档。相同键同 payload 返回原 receipt；同键不同 payload 为 409；revision 不同为 412。**不使用最后时间戳获胜。**

使用 `(base, localIntent, remoteCurrent)` 三方比较：

- 本机只是读过、没有改动：刷新远端即可；远端没有变化：正常提交。
- 原件/sourceRevision 改变、配对改变、未知 action/version：暂停，展示输入改变，不自动重放。
- 本机和远端同组编辑都变化：必须让用户处理。组为 geometry、color、timeAndCover、effectAndAudio；不能把裁剪 x 与 width、修剪与关键帧、effect 与 mute 拆开合并。
- 即使两端改不同组，首版只提出合并预览，让用户点“使用合并版本”后以最新 revision 创建新 operation；不在后台自行决定视觉结果。
- 两端规范化完整意图完全相同：可把本地意图标为与当前一致，但保留原操作 receipt/对账历史，不冒称本机 operation 曾被服务器接收。

冲突页显示同一帧的“我的版本/云端版本”、修改组与修订，不以系统时间排序推断谁更正确。动作：“保留我的草稿”“采用云端版本”“预览合并（可安全合并时）”“同步我的版本”。最后一个是在拉取最新状态后显式创建新 CAS 操作，可能再次冲突，绝不是无条件覆盖。采用云端也保留旧草稿 **30 天**可恢复；永久丢弃需要清楚列出对象。

远端删除/移入回收站：停止同步并保留草稿；提供恢复素材（有权限且用户动作）、导出已有副本或放弃。不得自动复活资产。PhotoKit 权限缩减：保留意图，停止读取不可见素材，不把不可见视为已删除。

### 10.4 PhotoKit 非事务冲突

写系统照片前检查 revision，提交后读回 adjustmentID/source fingerprint。PhotoKit 不提供跨 App 的通用 CAS 保证，检查与写入之间仍可能发生竞态；不能宣称服务器 ETag 能解决系统库竞态。若发现外部写入或无法证明当前结果，保留双方版本，标“需要检查系统照片”；不给出覆盖成功提示，后续要求用户重新选择基线或保存副本。

## 11. 权限、兼容性与迁移总表

| 场景 | 行为 |
|---|---|
| 无照片权限 | 云端已授权资源可继续；本机入口解释权限；不请求麦克风/相机/联系人 |
| 有限照片授权 | 仅可见资产可预览/编辑/分类；不要求为单项编辑先给全库；备份/清理仍遵循既有全库要求 |
| PhotoKit 写入拒绝 | Imora 草稿保留，单列系统写入失败；不偷偷改成新资产上传 |
| 云端 read-only/shared | 可按下载权限观看和允许的本机副本导出；不修改 owner 资产或相册；无 edit 权限就不入云端写队列 |
| 老服务器/未知 capability | 保持旧浏览、旧静态图编辑、旧 trim；第四批新意图只存在本机；以用户选定的普通副本上传为可选动作 |
| 服务器能力撤销/升级 | 任务转 blockedCapability，不删除；重新探测稳定身份与 capability 后可恢复，不能只比版本号 |
| macOS/visionOS 等项目平台 | 公共模型/解码不得破坏编译；没有验证的编辑 UI/PhotoKit 能力用运行时能力隐藏，不以 iOS 结果宣称全平台等价 |

迁移分四类：

1. 本机编辑 DB 用 schema version 逐步迁移，事务失败回到旧文件；未来版本只读保护，损坏隔离并保留原文件，不清空为新库伪装成功。
2. 遗留照片 edits 原样保留，前三批 `photo` action 与未知字段完整 round-trip；第四批不把它们改写为新类型。视频旧 trim 只在接口存在且能成功读取时映射到新草稿，必须记录原输入时间基；读取失败不当成没有 trim。
3. 服务端新增文档/receipt/job/facts/collection/movie 表，先读兼容、再按功能开写；旧列与旧成品保留。旧编辑写入口与新文档交叉保护详见契约，不允许两个写协议互相覆盖。回滚关闭功能写入，保留新表与草稿，不能用破坏性 down migration 丢用户编辑。
4. 聚合/分类是可重建索引，按算法版本分批回填；用户覆盖、影片 manifest、备份证据不可重建部分单独保存。回填不扫描原片、不传精确位置到外部服务、不阻塞首页。

## 12. 验收与待确认选择

详细案例见 [验收矩阵](03-acceptance-matrix.md)。每个模块同时覆盖本机未备份、已验证配对、纯云端；普通/有限/拒绝权限；新/旧服务器；前台/后台、离线/超时、账号切换。展示画面正确不能替代资源摘要、配对和删除资格的断言。

需用户确认的产品选择（均有可落地默认，不把技术探针当产品确认）：

1. 是否接受实况高级编辑首版保存在 Imora，系统完整实况写回经 G2 验证后单独开放；普通视频的系统写回仍列入本批。
2. 是否接受默认仅保存入口来源，配对资产同步云端需显式选择，冲突不自动覆盖。
3. 是否接受旅程为保守、可解释的建议，常驻地区由用户选填，缺定位则使用普通日期地点集合。
4. 是否接受回忆先无音乐/可导出内置音乐，首版导出以 1080p SDR 为默认，HDR 保真另设 G3 门槛。
5. 是否认可追加后的分期顺序 4P → 4A → 4B0 → 4B1/4C → 4D → 4E → 4F；4P/G5是图片体验基础，与4A一同放行；完整跨设备同步到4F才宣称完成。

确认本设计只确认方案；本会话不会因此开始实施。后续须用户另行明确授权实施，再从前三批实际完成版本建立独立工作区执行。
